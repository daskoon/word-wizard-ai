# Research: vision01 - Implement Auto-Vision

**Date**: 2026-01-20

## 1. Executive Summary
The current vision system is failing because it uses a generic prompt on high-noise Facebook Messenger screenshots. The model (`gemini-1.5-flash`) is unable to consistently isolate the 11x11 grid from the platform's UI elements.

## 2. Technical Context
- **Current Prompt**: `Extract 11x11 board and 7 rack tiles from this screenshot.` (`geminiService.ts:140`)
- **Board Configuration**: Hardcoded as 11x11 (`constants.ts:1`).
- **Data Flow**: `App.tsx` reads file -> sends raw base64 to `scanFullScreenshot`.
- **Output Format**: Compact JSON with keys `r` (rack) and `b` (121-char string).

## 3. Findings & Analysis
- **Hallucination Source**: The model reads chat bubbles, ads, and Messenger status bars as game tiles because it lacks spatial guidance.
- **Model Limitation**: `gemini-1.5-flash` is capable but `2.0-flash` offers significantly better visual grounding.
- **Landmark Dependency**: The game board uses specific colors for premium squares (Green TL corners). These are not being used as landmarks in the current prompt.
- **Image Size**: No client-side resizing means large payloads and potential timeouts or model rejection of high-res detail.

## 4. Technical Constraints
- **Grid Size**: Must remain 11x11 for Solo Challenge.
- **Response Format**: Must stick to the 121-char string protocol to minimize latency in the downstream logic phase.

## 5. Architecture Documentation
The project follows a "Compact Protocol" where the vision model acts as a digitizer, and the logic model acts as a grandmaster. This separation is sound but the digitization phase is the current bottleneck.
