Project Handover: WordWizard AI (WWF Assistant)
1. Executive Summary
Project Name: WordWizard AI
Purpose: A mobile-first web application that acts as an intelligent assistant for the "Words With Friends" (Solo Challenge) 11x11 game mode.
Core Mechanism: The app takes a screenshot of a game board, uses Multimodal AI (Gemini Flash) to parse the game state, and then uses a Reasoning AI (Gemini Pro) to calculate the optimal move.
Current Status: Functional MVP with significant UI polish, but suffers from reliability issues regarding computer vision on full uncropped screenshots.
2. Technical Stack & Environment
Framework: React 19 (Client-side only, Create React App / Vite style).
Language: TypeScript (Strict typing preferred).
Styling: Tailwind CSS (Utility-first, heavily dependent on Slate/Indigo color palettes).
Icons: Lucide React.
AI Provider: Google Gemini API (@google/genai SDK).
Vision Model: gemini-3-flash-preview (Optimized for speed/cost).
Logic Model: gemini-3-pro-preview (Optimized for complex reasoning).
State Management: React useState / useRef (No Redux/Zustand currently).
3. Architecture & Data Flow
The "Compact Protocol"
To reduce latency, the application avoids verbose JSON for the Vision step.
Request: Compressed grayscale JPEG (Base64).
Response Schema:
code
JSON
{
  "r": "ABCDEFG", // Rack tiles
  "b": "..."      // Flattened 121-char string (11x11) representing the board.
}
Rationale: Parsing a 121-char string is significantly faster and consumes fewer tokens than an array of coordinate objects.
Pipeline Steps
Ingestion: User selects an image.
Preprocessing (Client-Side):
Image is drawn to canvas.
Resized to max 800px width.
Converted to Grayscale.
Contrast increased (1.2x).
Exported as low-quality JPEG to minimize payload size.
Vision Analysis (Gemini Flash): Extracts the "r" (rack) and "b" (board string).
Verification (UI): User sees the digital twin of the board and can manually correct errors using the BoardGrid component.
Solving (Gemini Pro): The App sends the board state + game mode (Max Score, Defensive, Bingo) to the reasoning model.
Rendering: The AI returns a JSON object with the best move, score breakdown, and strategy text, rendered by MoveResult.
4. Component Structure
App.tsx: The state machine. Handles the transition between idle, scanning, ready_to_solve, and complete. Contains the image preprocessing logic.
services/geminiService.ts: The API layer. Contains the specific prompt engineering for "Optic Nerve" (Vision) and "Grandmaster" (Logic).
components/BoardGrid.tsx: Interactive 11x11 grid. Handles coordinate logic, tile placement, and editability.
components/RackInput.tsx: 7-slot input for managing user tiles.
components/MoveResult.tsx: Displays the high-level score and visualization toggle.
components/StrategyCard.tsx: Displays the "Why" behind the move.
components/ImageCropper.tsx: CRITICAL NOTE: This component exists in the filesystem but is currently disconnected in App.tsx. This is a major source of vision failure.
5. What Works vs. What Doesn't
What Works ✅
Logic Generation: When the board state is correct, Gemini Pro (gemini-3-pro-preview) is excellent at finding high-scoring moves and explaining strategy.
UI Aesthetics: The Tailwind design (Slate 50-900, Indigo accents, rounded corners) looks professional and modern.
Client-Side Optimization: The grayscale/resize logic in App.tsx successfully reduces API latency.
Board Interaction: The BoardGrid allows for easy manual corrections if the AI misses a tile.
What Doesn't Work / Pain Points ❌
Full Screenshot Vision: Sending a full phone screenshot (including battery bar, ads, footer nav) confuses the Vision model. It often hallucinates tiles in the UI areas or misaligns the 11x11 grid.
Missing Cropping Step: The ImageCropper.tsx is implemented but not instantiated. The user needs to crop the board and rack separately for 99% accuracy.
11x11 vs 15x15 Confusion: Occasionally, the model hallucinates a standard Scrabble size (15x15) despite the system prompt, causing array index overflows.
Hallucinations: In low-contrast screenshots, "I" is mistaken for "L" or blank tiles are missed.
6. Known Issues & "Gotchas"
Board Geometry: This app is hardcoded for 11x11 (WWF Solo). Standard WWF is 15x15. If the user uploads a standard board, the array logic breaks.
API Rate Limits: Uses the free tier of Gemini. Rapid retries or heavy testing will hit 429 errors.
Race Conditions: If the user clicks "Solve" while a previous request is hanging, state management can get de-synced.
7. Roadmap for Refactoring (If Starting Over)
If you are rebuilding this, follow this plan to fix the reliability issues:
Step 1: Integreate The Cropper (High Priority)
Do not send the full screenshot to Gemini.
User uploads image.
Show ImageCropper overlay.
User crops just the 11x11 grid.
Send only that square image to Gemini Vision.
(Optional) Second crop step for the Rack.
Step 2: Refine Vision Prompts
The current prompt relies on "Green TL corners". If the user uses a different board skin (e.g., Pink theme), this prompt fails.
New Strategy: Ask the AI to identify the grid structure regardless of color, or ask the user to specify the theme.
Step 3: Shift to Structured Output (Schema)
While the "Compact Protocol" (string parsing) is fast, it is brittle.
Change: Use responseSchema with Type.ARRAY of Type.STRING for the board rows. It is slightly slower but less prone to "off-by-one" indexing errors.
Step 4: Add Dictionary Validation
Currently, the AI hallucinates words sometimes.
Add: A client-side dictionary check (using a lightweight trie or bloom filter) to verify the AI's suggested word is actually in the WWF dictionary before displaying it.
